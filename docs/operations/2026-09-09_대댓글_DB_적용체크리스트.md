# 대댓글 DB 적용 체크리스트

대상: `202609090002_community_replies.sql`. 기존 [원격 DB 적용 상태](./2026-09-08_원격_DB_적용상태.md)와 별개의 후속 변경이다. 이 문서 작성 자체가 원격 적용 완료를 뜻하지 않는다.

## 현재 경계

- 로컬 구현·검증 및 코드 리뷰 후에 원격 적용 여부를 확인한다.
- 원격 미적용 환경에서는 기존 댓글을 유지하며 대댓글 기능은 활성화하지 않는다.
- 기존 `community-retention-every-minute` 비활성 상태를 유지한다. 대댓글 도입은 자동 파기 활성화 승인이 아니다.
- `.env.local`·토큰·서비스 키를 공개 문서나 Git에 저장하지 않는다.

## 적용 전

- [x] 로컬 통합 테스트와 기능/권한 리뷰 통과. SQL 4개, 전체 644개 통과 / 24개 건너뜀. 미존재 RPC 판별 지적을 수정하고 재리뷰 통과.
- [ ] 사용자에게 원격 적용 승인 확인.
- [ ] 연결된 프로젝트가 의도한 프로젝트인지 비밀값 노출 없이 확인.
- [ ] 원격 migration 이력이 `202609090001`까지인지 확인. 이력이 다르면 임의 repair/push 하지 않는다.
- [ ] 기존 게시글·댓글 수, 공개 상태, 원문 변경 여부 비교에 필요한 기준값을 비공개 방식으로 확보.
- [ ] 원격 스키마·데이터 백업을 Git 외부에 제한 권한으로 보관하고 실패 시 복구 범위를 확인. 백업 파일 내용은 채팅에 출력하지 않는다.
- [ ] 원격 migration은 단일 transaction에서 먼저 rollback 리허설. 기존 행의 부모 값은 모두 null이며 기존 필드는 변경되지 않아야 한다.

## 적용·확인

- [ ] 대댓글 migration과 이력 기록을 일관되게 반영. 기존 글·댓글 삭제, 보관 기간 변경, cron 활성화 금지.
- [ ] 원댓글 비공개 DTO에 본문·작성자·UUID·관리 사유가 노출되지 않음 확인.
- [ ] server-only RPC는 anon/authenticated/PUBLIC 실행 불가, service_role만 실행 가능 확인.
- [ ] 새 부모 필드의 직접 클라이언트 INSERT/UPDATE 불가 확인.
- [ ] schema cache 갱신 후 댓글 API의 `repliesEnabled` 및 기존 댓글 읽기 확인.
- [ ] 사용자 화면에서 답글 버튼과 오류 없는 기존 댓글 표시 확인.
- [ ] 새 테스트 글/댓글을 공개 DB에 만들 필요가 있으면 범위를 별도로 정하고 기존 데이터와 혼동하지 않게 기록.
- [ ] 실제 적용 결과·검증 범위·남은 항목을 이 문서 또는 작업 이력에 기록.

## 실패 대응

리허설 실패는 transaction rollback으로 끝내고 원인을 확인한다. 커밋 후 오류라면 앱의 새 답글 기능을 중지하고 기존 데이터 보존부터 확인한다. 부모 연결이 저장된 이후에는 migration을 무조건 되돌리거나 열을 삭제하지 않는다. 기존 댓글의 부모 연결·공개 상태를 보존하는 복구 계획을 세운 뒤 수행한다.
