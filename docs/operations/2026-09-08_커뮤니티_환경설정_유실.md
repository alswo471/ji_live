환경변수와 ignored 파일의 별도 보존을 확인하지 않고 정리한 것이 문제였다. 병합은 폴더를 자동 삭제하지 않는다. 커밋 보존과 로컬 설정 보존은 다른 조건이다.

## 복구 조사 — 2026-09-08

- 프로젝트와 주변 `Documents/ChatGPT`의 설정·백업 파일 경로를 확인했지만 커뮤니티의 완전한 설정 사본은 찾지 못했다.
- 해당 작업의 과거 기록에서 환경설정 백업 경로는 발견하지 못했다. 기록에 비밀값이 있을 것이라고 가정하지 않으며 원문 비밀값은 출력하지 않았다.
- `tmutil listlocalsnapshots /` 결과 로컬 snapshot은 없었다. 외장 Time Machine·사용자 password manager 등 별도 보관 여부는 확인되지 않았다.
- 루트 `.env.local`에는 Supabase publishable/secret key가 설정되어 있으나 URL·Turnstile site/secret key·community HMAC 설정은 없다. 미리보기 worktree에는 커뮤니티 연결 설정이 없다. 기존 시세 설정은 변경하지 않았다.
- DB 백업 스크립트는 DB dump용이며 환경변수 복구 수단이 아니다.

## 후속 조치

사용자 보관본이 있으면 필요한 설정을 안전하게 연결한다. 없으면 공급자 관리 화면에서 URL과 Turnstile 설정을 재확인하고, 필요한 경우에만 재발급한다. HMAC secret은 기존 abuse-key 집계에 영향을 주므로 임의로 재생성하지 않는다. 현재 단계에서는 키 생성·재발급·복사, 공개 flag 변경, DB 쓰기를 수행하지 않았다.

worktree 정리 가이드와 PC 이전 체크리스트를 보완했다. 사용자 승인 보관 경로·실제 보관 여부를 확인하지 못하면 폴더를 남겨 두며, Git clean 상태만으로 안전하다고 판단하지 않는다.

## 로컬 연결 복구

사용자가 Turnstile 키 두 개를 입력했고, HMAC secret 재생성과 로컬 연결을 승인했다. 기존 Supabase 키와 프로젝트 URL을 조합해 공개 Auth 설정 요청 HTTP 200을 확인한 뒤, 32바이트 난수로 HMAC secret을 새로 생성했다. 기존 IP 기반 집계와 연결되지 않는 점을 사전에 안내했다.

시세 설정을 유지하면서 필요한 여섯 항목을 루트 `.env.local`과 `ui-refresh/.env.local`에 병합했다. 두 파일은 소유자 읽기·쓰기 권한(600)으로 제한했다. 루트는 커뮤니티 비활성 상태를 유지하고 미리보기만 활성화·local proxy mode를 사용한다. 루트 사본은 worktree 삭제에 대비한 로컬 평문 사본이며, 디스크 장애 대비 암호화 백업을 대체하지 않는다. 설정 파일은 Git에 포함하지 않는다.

미리보기 서버는 `127.0.0.1:3002`에만 바인딩되어 있고, 목록 API HTTP 200과 기존 테스트 게시글 표시를 확인했다. 브라우저에서는 `127.0.0.1`의 Turnstile에 연결 오류가 표시됐지만 `http://localhost:3002/community`에서는 자동 검증 성공이 표시됐다. 주소에 따른 차이는 확인했으나 공급자 hostname 설정을 직접 검토한 것은 아니므로 원인을 확정하지 않는다.

확인 범위는 설정 저장·목록 조회·글쓰기 폼 표시·Turnstile 브라우저 성공까지다. 토큰의 서버 검증, 익명 로그인과 글 등록의 통합 검증 및 관리자 조치는 아직 하지 않았다. 공개 배포용 retention·문의·proxy 등 release gate 설정 전체를 복구한 것은 아니며 별도 확인이 필요하다.
