# 커뮤니티 worktree 정리 후 환경설정 유실

## 확인된 원인

2026-09-07 11:26 KST 작업 기록에서 에이전트가 develop 병합 후 `.worktrees/community-mvp`에 `git worktree remove`를 실행한 사실과 결과를 확인했다. `&&`로 이어진 branch 삭제에서 실패했으므로 앞선 폴더 제거와 prune은 완료됐다. 브랜치는 삭제되지 않았고 코드도 develop에 보존됐다.

환경변수와 ignored 파일의 별도 보존을 확인하지 않고 정리한 것이 문제였다. 병합은 폴더를 자동 삭제하지 않는다. 커밋 보존과 로컬 설정 보존은 다른 조건이다.

## 복구 조사 — 2026-09-08

- 프로젝트와 주변 `Documents/ChatGPT`의 설정·백업 파일 경로를 확인했지만 커뮤니티의 완전한 설정 사본은 찾지 못했다.
- 해당 작업의 과거 기록에서 환경설정 백업 경로는 발견하지 못했다. 기록에 비밀값이 있을 것이라고 가정하지 않으며 원문 비밀값은 출력하지 않았다.
- `tmutil listlocalsnapshots /` 결과 로컬 snapshot은 없었다. 외장 Time Machine·사용자 password manager 등 별도 보관 여부는 확인되지 않았다.
- 루트 `.env.local`에는 Supabase publishable/secret key가 설정되어 있으나 URL·Turnstile site/secret key·community HMAC 설정은 없다. 미리보기 worktree에는 커뮤니티 연결 설정이 없다. 기존 시세 설정은 변경하지 않았다.
- DB 백업 스크립트는 DB dump용이며 환경변수 복구 수단이 아니다.

## 후속 조치

사용자 보관본이 있으면 필요한 설정을 안전하게 연결한다. 없으면 공급자 관리 화면에서 URL과 Turnstile 설정을 재확인하고, 필요한 경우에만 재발급한다. HMAC secret은 기존 abuse-key 집계에 영향을 주므로 임의로 재생성하지 않는다. 현재 단계에서는 키 생성·재발급·복사, 공개 flag 변경, DB 쓰기를 수행하지 않았다.

worktree 정리 가이드와 PC 이전 체크리스트를 보완했다. 사용자 승인 보관 경로·실제 보관 여부를 확인하지 못하면 폴더를 남겨 두며, Git clean 상태만으로 안전하다고 판단하지 않는다.
