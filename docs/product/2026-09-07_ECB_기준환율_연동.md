# 달러·엔화·바트: ECB 일별 기준환율

## 결정과 의도

사용자가 일별 기준환율, 발표일·직전 발표일 비교, ECB 교차계산 표시를 승인했다. 기존 USDT/KRW는 Bithumb 거래상품 기반 합성환율이므로 USD/KRW로 이름만 바꾸지 않는다. 금 연동 PAXG·합성환율과 별도 영역으로 달러·100엔·바트 기준환율을 배치한다.

## 계산 원리

ECB는 EUR 1당 각 통화 수량을 발표한다. 같은 날짜의 원본만 사용한다.

- USD 1당 KRW = `EUR/KRW ÷ EUR/USD`
- JPY 100당 KRW = `EUR/KRW ÷ EUR/JPY × 100`
- THB 1당 KRW = `EUR/KRW ÷ EUR/THB`
- 등락률 = `(이번 발표일 교차환율 ÷ 직전 발표일 교차환율 − 1) × 100%`

계산 중 반올림하지 않고 표시할 때 소수점 둘째 자리까지 반올림한다. 비교일은 달력상 전날이 아니라 데이터에 실제 존재하는 직전 발표일이다. 이전 값이 없으면 등락률을 만들지 않는다. 은행 매매기준율·현찰 매수매도율·실시간 외환시장 체결가가 아니다.

## 수집과 장애 대응

`/api/market/reference-fx`를 기존 시세 API와 분리했다. ECB 90일 XML을 우선 요청하고, 실패하면 Frankfurter v2의 `base=EUR&quotes=KRW,USD,JPY,THB&providers=ECB` 최근 14일 데이터를 사용한다. 여러 기관 혼합 기본값은 사용하지 않는다. 두 경로는 동일한 계산 함수를 사용한다.

직접 XML 다운로드·계산은 Node에서 정상이나 로컬 개발 서버 실행환경의 ECB fetch가 `internal error`로 반복 실패했다. 실행환경 내부 원인까지는 확인하지 못했으므로 인증서·보안 설정을 끄지 않았다. 대체 경로에서 같은 ECB 원본값과 API 정상 응답을 확인했으며, 화면에 `데이터 전달: Frankfurter · ECB 단일 공급자`를 표시한다.

서버 프로세스별 1시간 캐시·동시 요청 병합, 각 경로 5초 timeout, 전체 실패 시 기존 회로 차단·지연 재시도 정책을 사용한다. 이전 정상값을 반환할 때 stale을 표시한다. 발표일이 10일 넘게 오래되면 숫자를 반환하지 않는다. 10일은 서비스의 보수적인 운영 상한이며 ECB 발표 일정 보장이 아니다. 브라우저는 보이는 탭에서 5분마다 확인하고 중복 요청·unmount 후 상태 갱신을 막는다.

날짜 역순·주말·양수 아닌 값·통화 누락·중복 데이터·미래/잘못된 날짜를 검사한다. XML은 관찰한 Cube 형식만 해석하고 DTD/entity 및 외부 리소스 해석을 허용하지 않는다. 형식 변경은 미제공으로 처리한다.

## 참고자료와 적용 범위 — 2026-09-07 확인

- [ECB 기준환율](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html): 영업일 기준 발표되는 정보용 지표이며 거래용 이용을 권장하지 않는다는 설명을 확인했다.
- [ECB 이용 조건](https://www.ecb.europa.eu/services/using-our-site/disclaimer/html/index.en.html): 정확한 재현·ECB 출처 표기·가공 여부 명시 조건을 반영한다. 원문은 새 창의 전체 페이지로 연결한다. 추후 유료 판매 시 무료 원문 제공 사실 고지 등 추가 조건을 다시 확인한다.
- [Frankfurter v2](https://frankfurter.dev/): ECB 필터·기간 조회·상업적 API 이용 안내를 확인했다. 기초 데이터 약관과 API 이용 조건은 별개라는 점을 유지한다.

이 문서는 적용 근거와 구현 이력이며 포괄적인 법률 적합성 보증이 아니다.
