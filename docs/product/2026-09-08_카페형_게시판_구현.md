# 카페형 커뮤니티·조회수·추천 구현

## 결과

기존 커뮤니티의 인증·신고·삭제·관리자·보존 정책을 유지하면서 목록을 제목 중심 게시판으로 정리했다. 데스크톱은 제목·작성자·작성일·조회·추천 열을 보여 주고, 모바일은 제목 아래에 메타정보를 묶는다. 특정 서비스의 로고·색상·자산을 복제하지 않고 지투라이브 테마와 기존 컴포넌트를 재사용했다.

`/community/write`는 기존 `PostForm`·익명 세션·Turnstile·재시도 idempotency key를 재사용한다. 성공하면 서버가 반환한 게시글 ID의 상세로 이동하고, 취소 동선과 페이지를 떠나면 초안이 사라진다는 안내를 표시한다.

## 집계 계약

- 조회: 검증된 actor·게시글 조합의 `last_counted_at`로 rolling 24시간을 적용한다. 23시간 59분에는 증가하지 않고 24시간 경계부터 다시 1회 반영한다.
- 추천: toggle이 아닌 `recommended: true | false`를 보내 재시도해도 같은 결과가 된다. 본인 글·비공개 글·삭제 글·활성 제재 사용자는 DB에서 거부한다.
- 동시성: 게시글 행을 먼저 잠그고 unique actor·post 관계를 갱신해 중복 증가와 음수를 막는다.
- 요청 제한: 조회는 60회/60초, 추천·취소는 합계 20회/60초를 actor와 daily HMAC에 각각 적용한다. 원본 IP는 저장하지 않는다.
- 권한: browser의 anon/authenticated role은 집계 table에 쓰거나 RPC를 실행할 수 없다. 서버가 JWT·Turnstile·trusted proxy 경계를 검증한 뒤 service role로만 호출한다.

## 오류와 보존

집계 migration이 없거나 집계 API가 실패해도 게시글 본문과 댓글 읽기는 계속한다. 알 수 없는 수치는 0으로 꾸미지 않고 `—`로 표시하며 상세에 재시도 동선을 제공한다. 조회 receipt는 마지막 반영 후 24시간이 지나면 hourly `pg_cron`이 정리하고, 누적 조회수는 유지한다. 추천 관계는 취소 시 즉시 삭제하고 사용자·게시글 실제 파기 시 cascade한다. 기존 삭제 콘텐츠 1년 보관과 legal hold는 변경하지 않았다.

브라우저 데이터 삭제나 새 기기로 새 익명 actor가 만들어지면 동일 사람을 완전히 판별할 수 없다. 이 문서는 법적 적합성을 보증하지 않는다.

## 검증과 배포 조건
