# 지투라이브 포트폴리오 케이스 스터디

## 1. 한 줄 소개

지투라이브는 국내 정규장 이후에도 움직이는 해외 주식 연동 파생상품을 이용해 한국·미국 주식의 24시간 참고 추정가를 제공하고, 실제 거래상품과 추정값의 차이를 투명하게 설명하는 멀티자산 시장 대시보드다.

프로젝트는 지민재가 기획, 공개 데이터 API 통합, UI/UX, 테스트, GitFlow, CI/CD와 배포까지 제품 개발 전 과정을 학습하고 증명하기 위한 개인 프로젝트다.

## 2. 왜 이 프로젝트를 기획했는가

국내 증권 앱은 정확한 실제 시세와 거래 기능을 제공하지만 정규장이 끝나면 한국 주식의 대표 가격은 멈춘다. 반면 해외 시장의 한국 주식 연동 파생상품은 야간과 휴장 시간에도 움직이며 다음 국내 시장에 대한 기대를 반영한다.

처음에는 증권사 Open API로 실제 시세와 개인 보유종목을 표시하는 대시보드로 시작했다. 개발 과정에서 다음 문제가 드러났다.

- 개인 API 자격증명과 고정 IP는 공개 다중 사용자 서비스에 맞지 않았다.
- 5초 폴링이 중복되면서 429 요청 제한 오류가 발생했다.
- 개인 보유종목은 공개 배포판에 노출할 수 없었다.
- 실제 시세의 재배포와 광고형 서비스에는 별도의 데이터 권리가 필요했다.
- 주말·휴장 중에는 실제 주식 가격 자체가 존재하지 않는다.

이 문제를 계기로 제품의 질문을 바꿨다.

> 실제 주식 시세를 복제하는 대신, 공개 데이터만으로 24시간 시장 기대를 얼마나 정직하고 유용하게 표현할 수 있는가?

## 3. 기획 변화의 역사

### 0.1: 실제 시세와 개인 자산 대시보드

- Toss Invest API로 한국·미국 주식과 개인 보유종목을 표시했다.
- 브라우저에서 5초마다 dashboard API를 조회했다.
- 429 오류와 공개 배포 환경의 고정 IP·재배포 문제가 확인됐다.

### 0.3: cache와 공개 화면 정리

- 같은 cache miss의 동시 요청을 하나로 합쳤다.
- 공급자별 TTL, 429 `Retry-After`, 회로 차단을 추가했다.
- 공개 배포판에서 개인 보유자산을 제거했다.
- GitFlow, 한국어 중심 Conventional Commit, CHANGELOG와 기술 문서를 정착시켰다.

### 0.4: 24시간 파생 추정가로 전환

- 공개 배포판에서 Toss 의존성을 제거했다.
- Hyperliquid·Binance 파생상품과 Bithumb 합성환율을 사용했다.
- 실제 주식 시세가 아니라 `24시간 추정가`임을 UI에 표시했다.
- 공급자, 기준 시각, 비교 기준과 환산 근거를 노출했다.

### 다음 개편: 세션 인식과 검증 가능한 추정가

- 프리·KRX 정규·NXT 애프터·야간을 구분한다.
- 한국 주식 원화 추정 candle과 상세 OHLC를 제공한다.
- 거래량은 `추종상품 거래량`으로 의미를 분리한다.
- 공급자 24시간 등락률과 국내 종가 기준 등락률을 혼합하지 않는다.
- 동일 시각 기준 오차를 수집해 종목별 신뢰도를 평가한다.

## 4. 핵심 알고리즘

### 현재 원화 추정가

```text
estimatedKrw(t)
= derivativePrice(t) × bithumbKrwUsdt(t)
```

- Hyperliquid 한국 주식 연동 상품은 `markPx`를 사용한다.
- Binance 토큰화 주식 무기한선물은 `lastPrice`를 사용한다.
- Bithumb `KRW-USDT`는 은행 고시환율이 아니라 거래상품 기반 합성환율이다.
- 입력 하나라도 없거나 오래됐으면 가격을 만들지 않는다.

### 기준점 보정 후보

```text
calibration
= verifiedDomesticClose
/ (derivativeAtClose × fxAtClose)

calibratedEstimate
= derivativeNow × fxNow × calibration
```

보정은 무조건 적용하지 않는다. 실제 종가의 사용 권리와 기준 시각이 검증되고, 백테스트에서 지속적인 편향을 줄인다는 근거가 있을 때만 적용한다.

### 원화 candle

파생상품 candle과 같은 시각의 환율 candle을 먼저 1분 단위에서 결합한 뒤 15분·1시간·4시간·일·주·월봉으로 집계한다. 현재 환율을 모든 과거 candle에 곱하지 않는 이유는 과거 차트를 왜곡하기 때문이다.

### 오차율

```text
APE(t)
= abs(estimate(t) - actual(t)) / actual(t)
```

20분 지연 실제값은 20분 전에 저장한 추정가와 비교한다. 현재 추정가와 지연값을 비교하면 시장 움직임과 모델 오차가 섞이기 때문이다.

## 5. KRX에는 가깝고 NXT에는 차이가 나는 이유

Hyperliquid의 삼성전자 상품은 KRX `005930` 보통주 1주를 참조하고 원화 가격을 달러로 환산한다. 따라서 정규장에는 KRX 가격과 가까워지는 것이 자연스럽다.

NXT는 KRX와 별도의 주문장과 체결을 가진 대체거래소다. 같은 종목이어도 참여 주문, 유동성, 마지막 체결 시각이 달라 가격이 순간적으로 다를 수 있다. NXT 공식 공개 화면은 20분 지연이므로 현재 추정가와 그대로 비교하면 시간 차이까지 포함된다.

제품은 다음 원칙을 사용한다.

- KRX 정규장에는 KRX 추종을 대표 기준으로 삼는다.
- NXT 프리·애프터에는 NXT를 오차 평가 기준으로 삼는다.
- KRX와 NXT 실제값을 보유하지 않으면 실시간 시세라고 표시하지 않는다.
- NXT와 다르다는 이유만으로 KRX 추종 가격을 강제로 보정하지 않는다.

## 6. 중요한 기술적 의사결정

### 서버 cache로 방문자 수와 외부 호출 수 분리

브라우저 1,000명이 접속해도 공급자 API를 1,000번 호출하지 않는다. 서버가 공급자별 snapshot을 한 번 갱신하고 모든 방문자에게 cache된 결과를 제공한다.

### 공급자별 장애 격리

Hyperliquid 장애가 Bithumb 코인과 Binance 자산까지 막지 않도록 결과를 자산군별로 합성한다. stale 값에는 마지막 정상 시각을 표시하고 한계를 넘으면 숨긴다.

### 실제값과 추정값을 타입으로 구분

`actual-product`, `derived-estimate`, `unavailable`을 데이터 계약에서 구분한다. UI 문구만으로 구분하면 새로운 화면에서 실수로 실제값처럼 표시할 가능성이 있기 때문이다.

### 미지원은 숫자보다 낫다

검증되지 않은 심볼, 계약 단위 또는 환율에는 예시 가격이나 임의 fallback을 사용하지 않는다. 금융 화면에서는 빈 상태가 잘못된 확신보다 안전하다.

### 증권사 API 제거

증권사 수가 많다는 사실과 공개 재배포 권리는 별개의 문제다. 개인 거래용 API를 여러 개 연결하는 대신 공개 서비스에 적합한 데이터 권리와 확장성을 우선했다.

## 7. 해결한 주요 문제

### Toss API 429

원인:

- 여러 화면과 방문자가 같은 5초 주기로 계좌·시세 API를 반복 호출했다.

해결:

- 데이터별 TTL cache
- 같은 요청의 in-flight 병합
- `Retry-After` 기반 재시도
- 공급자별 회로 차단
- 숨은 브라우저 탭 polling 중단

### 실제값처럼 보이는 고정 예시 가격

원인:

- 공급자 연결 전에도 샘플 숫자가 표시돼 사용자가 실시간 데이터로 오인했다.

해결:

- loading, stale, unavailable 상태를 분리했다.
- 공급자와 기준 시각을 함께 표시했다.

### 한국 주식 차트와 OHLC 미제공

원인:

- 파생 candle은 USD·USDT, 화면 가격은 KRW이므로 같은 의미를 보장할 수 없었다.
- 과거 모든 candle에 현재 환율을 곱하면 차트가 왜곡된다.

개편:

- 파생 candle과 시점별 환율 candle을 시간 정렬해 원화로 변환한다.
- 변환 근거가 없으면 차트를 숨기는 기존 안전 원칙은 유지한다.

## 8. 품질 검증 전략

- 단위 테스트: 환산, session 경계, candle 집계, stale와 이상값
- 통합 테스트: dashboard 부분 장애, candle API, UI 의미 표기
- 회귀 테스트: 전체 테스트·lint·build
- 데이터 검증: 최소 20거래일 세션별 MdAPE와 P95 APE
- 종목 확대: 60거래일 데이터와 mapping·계약 단위 검증 후 결정

목표 오차는 정확도 주장값이 아니라 출시 합격선으로 사용한다.

| 세션 | MdAPE 목표 | P95 APE 목표 |
| --- | ---: | ---: |
| NXT 프리 | 1.0% 이하 | 3.0% 이하 |
| KRX 정규 | 0.5% 이하 | 1.5% 이하 |
| NXT 애프터 | 1.0% 이하 | 3.0% 이하 |

## 9. 예상 면접 질문과 답변

### 왜 실제 시세 대신 추정가를 만들었나요?

실시간 KRX 데이터는 단순 기술 문제가 아니라 정보이용 계약과 재배포 권리의 문제였다. 개인 증권사 API로 프로토타입은 만들 수 있었지만 광고형 공개 서비스로 확장하기 어려웠다. 그래서 공개 파생상품 데이터를 이용하되 실제 주가라고 주장하지 않고 24시간 시장 기대를 보여주는 제품으로 문제를 재정의했다.

### 추정가 알고리즘은 무엇인가요?

한국 주식을 참조하는 해외 파생상품 가격을 Bithumb KRW-USDT 합성환율로 원화 환산한다. 공급자와 환율의 최신성·단위·범위를 검증하고, 검증된 국내 종가가 확보되면 백테스트를 통과한 종목에 한해 기준점 보정을 적용한다.

### 왜 현재 환율을 과거 차트에 곱하지 않았나요?

그 방식은 과거의 환율 변화를 무시해 OHLC를 왜곡한다. 파생 1분 candle과 동일 시각의 환율 candle을 결합한 뒤 상위 봉으로 집계하는 순서를 선택했다.

### NXT와 KRX 가격이 다른데 어떤 값을 기준으로 하나요?

두 시장은 별도 주문장이므로 같은 시각에도 마지막 체결가가 다를 수 있다. 현재 Hyperliquid 상품이 KRX 주식을 참조하므로 정규장 대표 기준은 KRX로 두고, NXT는 프리·애프터 세션의 검증 기준으로 분리한다.

### 오차율을 어떻게 검증하나요?

동일 시각의 snapshot끼리 APE를 계산하고 세션별 MdAPE, P95, 방향 일치율을 집계한다. 지연 실제값을 현재 추정가와 비교하지 않는다. 최소 20거래일 뒤 1차 평가하고 60거래일 뒤 종목 확대를 결정한다.

### 1,000명이 접속하면 API 호출도 1,000배가 되나요?

아니다. 공급자별 cache와 in-flight 병합으로 서버가 하나의 snapshot을 만들고 방문자에게 fan-out한다. 호출량은 방문자 수가 아니라 cache 갱신 주기에 가깝게 유지된다.

### 공급자 하나가 장애를 일으키면 어떻게 되나요?

자산군별 요청을 병렬로 분리하고 공급자별 회로 차단을 사용한다. 해당 종목만 stale 또는 unavailable로 바꾸고 다른 시장 데이터는 계속 제공한다.

### 왜 데이터를 찾기 쉬운 웹사이트에서 크롤링하지 않았나요?

기술적으로 가능하더라도 재배포 권리, 이용약관, DOM 변경과 차단 위험 때문에 제품 기반으로 삼지 않았다. 공식 공개 API와 권리가 확인된 데이터만 사용한다는 원칙을 선택했다.

### 가장 어려웠던 점은 무엇인가요?

가격을 가져오는 코드보다 데이터의 의미를 정확히 모델링하는 일이 어려웠다. 실제 상품, 파생 추정가, 지연값, stale과 미제공을 같은 숫자 필드로만 다루면 UI가 사용자를 오도한다. 이를 타입, 문구, 기준 시각과 테스트로 일관되게 유지하는 데 집중했다.

### 아쉬운 점과 다음 단계는 무엇인가요?

정식 KRX·NXT 실제 시세 계약이 없어 추정가를 실제 가격으로 보장할 수 없다. 다음 단계는 세션별 오차 snapshot을 축적하고, 계약 가능한 공식 공급자가 확보되면 실제값을 별도 계층으로 추가하는 것이다.

## 10. 프로젝트에서 증명하는 역량

- 모호한 아이디어를 데이터 계약과 UI 정책으로 구체화하는 제품 기획
- 외부 API rate limit, stale, timeout과 부분 장애 처리
- 금융 데이터의 단위·기준 시각·비교 기준 모델링
- React·TypeScript 기반 반응형 대시보드와 접근성
- TDD, 회귀 테스트, GitFlow와 원자적 커밋
- 공개 배포에서 개인정보·API 자격증명·데이터 권리를 고려하는 운영 설계
- 시행착오와 의사결정을 문서로 남기는 기술 커뮤니케이션
