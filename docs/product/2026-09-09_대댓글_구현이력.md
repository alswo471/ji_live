# 대댓글 구현 이력

## 요청과 결정

사용자는 네이버 카페처럼 읽기 쉬운 커뮤니티, 답글과 기본 이모지 입력을 요청했다. 전체글·공지사항·추천순 인기글 및 이모지 입력을 먼저 구현한 뒤 대댓글로 이어갔다.

원댓글 삭제 후 다른 사람의 답글까지 사라지는 문제를 피하기 위해, 원댓글의 원문·작성자는 감추고 공개 답글은 유지하는 정책을 사용자 확인 후 선택했다. 깊이는 한 단계로 제한해 모바일에서도 대화 구조가 복잡해지지 않게 한다. 이는 제품 정책이며 법에서 이 표시 방식을 요구한다는 뜻이 아니다.

## 구현 원리

- 댓글에 선택적인 부모 ID를 연결한다. 다른 게시글의 댓글, 대댓글, 숨김·삭제 원댓글에는 새 답글을 달 수 없다.
- 공개 답글이 있는 비공개 원댓글은 `삭제·숨김 처리된 댓글입니다.`로 표시한다. 원문·작성자·사용자 UUID·관리 사유는 공개 응답에 담지 않는다.
- 원댓글과 각 답글 목록은 별도 페이지로 조회한다. 커서는 게시글·부모 범위와 원본 timestamp·ID에 묶어 다른 목록에 섞이지 않게 한다.
- 작성은 서버 전용 RPC에서 게시글·부모 상태와 중복 요청을 함께 검사한다. 브라우저의 버튼 숨김에만 권한 검사를 의존하지 않는다.
- 답글은 기존 이모지 입력·신고·본인 삭제·Turnstile·댓글 작성 제한을 공유한다. 실패한 입력과 이미 읽은 답글은 보존하고 인증·부모가 바뀐 뒤 늦게 도착한 응답은 버린다.
- 원댓글이 실제 파기되면 부모 연결만 null로 바꾸어 자식 댓글을 일반 댓글로 유지한다. 기존 1년 보관·legal hold와 자동 파기 설정은 변경하지 않는다.

## 검증과 적용 상태

로컬 SQL에서 권한 거부, 부모 연결 검증, 재시도 충돌, 숨김 원문 비노출, 작성자 삭제 및 실제 부모 삭제 후 답글 보존, 소수점 이하 timestamp 페이지 경계, 동시 숨김·작성 충돌을 검사했다. 테스트 데이터는 별도 UUID로 생성해 rollback하거나 해당 데이터만 정리했으며 기존 사용자 데이터를 삭제하지 않았다.

- 최초 전체 테스트 641개 통과, 24개 건너뜀. 별도 활성화한 로컬 DB 통합 테스트 4개 통과.
- TypeScript·lint·build 통과. 별도 리뷰에서 다른 스키마·접두사가 붙은 함수 오류까지 구형 DB로 오인할 수 있는 정규식 문제를 발견해, 정확한 public 함수 이름으로만 판별하도록 수정했다. 실패 테스트 3개 재현 → 관련 49개 통과 → 재리뷰 통과. 수정 후 전체 644개 통과, 24개 건너뜀을 확인했다.
- `202609090002_community_replies.sql`은 로컬 DB에만 적용하고 migration 이력을 등록했다.
- 현재 원격 DB에는 미적용. 미리보기의 기존 댓글 API는 HTTP 200, `repliesEnabled:false`로 확인했으며 원격에서 답글 작성까지 검증했다는 의미는 아니다.
- 원격 적용은 [DB 적용 체크리스트](../operations/2026-09-09_대댓글_DB_적용체크리스트.md)의 승인·백업·리허설 후 진행한다. 자동 파기 활성화나 push·merge와는 별개다.

최종 통합 리뷰는 브랜치 분기점 `6d99347`부터 `e920c08`까지 18개 커밋의 게시판·조회수·추천·공지·인기글·이모지·대댓글을 함께 검토했다. 차단 결함이나 추가 개선 지적 없이 코드 병합 가능 판정을 받았다. 이는 원격 DB 적용·실제 답글 작성 검증·공개 배포 승인을 뜻하지 않는다. 기능 작업 공간과 검토 이력은 보존했다.
