# 일반·공지·필독 구현 기록

## 요청과 범위

사용자가 승인한 `일반 / 공지 / 필독` 작성·변경, 공지 강조·상단 정렬과 이미지의 날짜 표기를 구현했다. 근거는 [승인 설계](../superpowers/specs/2026-09-09_공지_필독_선택_설계.md)와 [이미지 및 공식 권한·정렬 자료](../reference/2026-09-09_공지_권한_정렬_참고자료.md)다. 좌측 메뉴·인기글·대댓글·이모지는 포함하지 않았다.

## 화면과 권한

- 관리자 JWT·membership과 DB 준비 확인 후 작성/상세의 종류 선택기를 표시한다. 기본은 일반이다. 일반 사용자는 기존 공개 작성 API를 사용한다.
- 일반으로 변경하면 강조·고정이 해제된다. 실패 시 입력/선택을 유지하며 동기 중복 제출을 차단하고 저장 중 선택기를 비활성화한다.
- 세션 토큰 변경 시 권한 확인을 무효화하고 쓰기 직전 최신 토큰을 확인한다. 서버 매 요청 및 SQL 트랜잭션에서 관리자 자격을 검증한다.
- 붉은 텍스트 배지에 공지/필독을 명시하고 라이트/다크 색상과 줄바꿈 방지를 적용했다. 날짜는 서울 시간 `2026.04.15.`이고 상세 시각도 서울 시간이다.

## 저장·감사·정렬

`community_posts.kind`는 세 종류만 허용한다. 생성된 `kind_rank`와 visible 부분 인덱스로 필독→공지→일반, 작성일·ID 내림차순을 **DB 조회 단계**에서 적용한다. 커서는 종류 순위와 PostgreSQL 마이크로초 timestamp를 보존한다. 구형 두 필드 게시글 커서는 명시적 새로고침 오류를 반환하고 댓글 커서는 계속 지원한다. 조회 도중 종류가 변경되면 목록을 새로고침해야 하며 스냅샷 세션은 제공하지 않는다.

관리자 생성은 글·종류·프로필·감사를 한 트랜잭션으로 저장한다. 키별 잠금과 unique 제약으로 재시도 중복 글/감사를 막고 다른 작성자의 키를 거부한다. 숨김·삭제 글은 생성 재시도나 종류 변경으로 공개하지 않는다. service_role의 일반 insert/update에는 종류 열 권한이 없으며 anon/authenticated는 직접 쓰기 및 RPC 실행이 차단된다.

`community_moderation_actions`에 `kind_change`와 이전/새 종류를 추가했다. 관리자·대상·종류·시각과 고정 형식의 사유만 저장하고 제목/본문 snapshot은 생성하지 않는다. 기존 1년 감사 보관·legal hold·콘텐츠 파기 의존 관계와 운영 로그 표시를 사용한다.

## 연결·배포 경계

관리자 GET은 권한과 readiness를 분리한다. 종류 migration이 없으면 선택기를 숨기고 연결 상태를 안내한다. 공개 읽기는 missing-column 오류에만 이전 DB로 fallback하며 공지/필독 커서를 일반 정렬로 변환하지 않는다. 관리자 API는 no-store이고 provider 오류를 노출하지 않는다.

DB 변경은 기존 **로컬 Supabase Docker의 additive migration**뿐이다. 볼륨 reset, 원격 migration, push, merge는 수행하지 않았다. 부모가 확인한 원격 DB는 `202609030003`까지이므로 선행 관리자/보관/집계 migration과 이번 `202609090001`은 별도 승인 후 순서대로 적용해야 한다. 운영 관리자 저장이 완료된 상태가 아니다.

## 검증

TDD로 날짜 자정 경계, 종류 위조 거부, 관리자 권한/DB 준비/오류, 원자 생성과 멱등성, 변경/해제, 숨김/삭제 차단, 실제 SQL 역할 권한과 정렬, 커서 마이크로초, 선택기·실패·중복 제출을 검증했다. SQL 검사는 매번 독립 UUID fixture를 만들고 해당 데이터만 정리한다.

부모 브라우저 QA는 기존 원격 schema를 읽는 미리보기에서 수행했다: 목록 `2026.09.04.`, 상세 날짜·서울 시각, 본문·댓글 읽기, 비관리자 선택기 비노출, 라이트/다크와 390×844 모바일. 집계 `—`/연결 실패 안내는 기존 원격 상태다. 관리자 생성·변경과 DB 정렬은 로컬 SQL 및 API/컴포넌트 검사로 검증했으며 운영 검증과 구분한다.

검증 결과: 전체 `pnpm test`는 615 통과·19 skip이다. 이 중 종류 6개·집계 7개는 별도 `RUN_LOCAL_SUPABASE_TESTS=true` 실행에서 실제 로컬 SQL로 13개 모두 통과했으며, 기존 보안 통합 6개는 이번 실행에서 활성화하지 않았다. `pnpm exec tsc --noEmit`, `pnpm lint`, `pnpm build`도 통과했다. lint 후 의미 요소 수정은 관련 13개 테스트·tsc·lint로 재검증했다. build에는 기존 vinext 정적 route 분류 안내와 plugin timing 경고가 있었으며 exit 0이었다.

TDD·UI/UX Pro Max·minjae-commit 스킬을 적용했다. UI 지침에 따라 보이는 label, 44px 조작 영역, 저장 중 상태, 실패 시 입력 유지와 텍스트 구분을 반영했다.
