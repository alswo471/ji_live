# 댓글 이모지 입력

## 요구와 선택

사용자가 네이버 카페형 커뮤니티에 대댓글과 이모티콘 사용을 요청하고 이어서 진행하도록 지시했다. 별도 이미지 스티커·라이선스가 있는 캐릭터 팩이나 외부 SDK 대신 기본 Unicode 이모지 12개를 입력하는 작은 선택 패널을 추가했다. 새로운 계정·외부 서비스·DB 변경이 필요하지 않다.

대댓글은 원댓글이 삭제·숨김 처리되었을 때 다른 사람이 쓴 답글의 공개 여부가 아직 확정되지 않아 이번 구현에 포함하지 않았다. 1년 보관 기간을 변경하거나 임의로 답글까지 삭제하는 정책을 도입하지 않는다.

후속 결정: 원댓글 원문·작성자만 감추고 공개 답글은 유지하는 정책을 사용자 확인 후 별도 구현했다. [대댓글 구현 이력](./2026-09-09_대댓글_구현이력.md)을 참고한다. 위 문단은 이모지 구현 당시의 범위를 보존한 기록이다.

## 동작

- 댓글 입력란 아래 이모지 버튼을 누르면 선택 패널이 열린다. 선택한 이모지는 현재 커서에 삽입하거나 선택한 글자를 대체한다.
- 선택 후 입력란으로 초점을 돌리고 커서를 삽입 위치 뒤로 이동한다. 패널의 버튼에서 Escape를 누르면 닫고 이모지 열기 버튼에 초점을 돌린다.
- 이모지는 일반 텍스트로 기존 댓글 API에 전송한다. HTML·이미지·링크를 삽입하지 않으며 기존 서버 검증을 우회하지 않는다.
- UTF-16 단위인 textarea maxLength 대신 서버와 같은 Unicode 코드 포인트 수로 제출을 검증한다. 😀는 1개, variation selector가 붙은 ❤️는 2개로 계산되며 시각적 글자 수(grapheme)와 항상 같지는 않다. 기존 서버 정책을 유지한 것이다.
- 1,000자를 넘기는 이모지 삽입은 거부한다. 직접 입력한 초과 문자열도 제출할 수 없다.
- 전송 중에는 입력을 잠그고 동기 플래그로 중복 제출을 막는다. 실패하면 본문과 요청 키를 보존하며, 내용을 수정하면 새로운 요청 키를 사용한다.
- 폼별 고유 ID, 이모지별 이름, 선택 패널의 fieldset, 44px 최소 버튼 높이를 적용한다. 실제 모양은 운영체제 이모지 글꼴에 따라 다를 수 있다.

## 검증·참고

- 테스트를 먼저 작성해 선택 버튼 미구현과 중복 제출 실패를 확인한 후 구현했다.
- 이모지 선택·커서 삽입·일반 댓글 전송, 1,000 이모지 한도, 중복 제출·실패 후 같은 키 재시도 테스트 통과.
- 실제 localhost 상세 화면에서 패널 열기와 😀 삽입 후 1/1000 표시·입력란 초점 복귀 확인. 댓글 전송 버튼은 누르지 않았다.
- 전체 626 passed / 20 skipped, 타입 검사·lint·빌드 검증. 접근성 lint가 지적한 일반 div 키 이벤트/role을 fieldset 및 개별 버튼 키 처리로 보완했다.
- 별도 읽기 전용 코드 리뷰에서 차단 결함 없음. 원격 DB migration·설정 변경·댓글 생성은 하지 않았다.
- 참고한 프로젝트 코드: `lib/community/validation.ts`의 `getCharacterLength` 및 `validateCommentInput`, 기존 `CommentForm` 요청 키/실패 처리, `Button`·`Textarea` 스타일.
- UI/UX Pro Max의 semantic control·키보드 조작·터치 영역 지침, TDD와 minjae-commit 스킬을 적용했다. 타사 이모티콘 이미지나 코드를 복제하지 않았다.
