# 공식 일별 데이터 연동

## 왜 추가했는가

기존 해외 파생상품의 원화 환산값은 실제 KRX·NXT 주식 체결가가 아니다. 같은 화면에서 참고 추정 흐름을 보되 공식 과거 기록을 별도로 확인할 수 있도록 분리했다. 공식 일별 종가는 기준 시점이 다르므로 현재 추정가의 오차율 검증용 분모로 사용하지 않는다. 공급자 선정 근거는 [공개용 시세 공급자 검토](../reference/2026-09-07_공개용_시세_공급자_검토.md)에 있다.

## 화면과 구현 범위

- 국내 주식 상세: 현재 추정 가격 → 기존 차트 → 차트 수치·근거 팝업 → 공식 일별 종가·등락률·거래량 → 펼칠 수 있는 최근 기록 표. 조회 기간은 90일이며 비거래일을 보간하지 않는다.
- `/indicators`: 코스피·코스닥 공식 일별 카드. 각 지수의 기준일을 별도로 표시하며 환율·PAXG·BTC 심리는 유지한다.
- `/?market=etf`: 국내 ETF 일별 거래량 TOP 10. 날짜와 종가·전일 대비·거래량을 표시한다. ETF 메뉴의 준비 badge와 화면의 5초 갱신 안내는 제거했다.
- 공통 하단 출처 팝업에 세 공식 출처와 발표 지연·순위 산정 기준을 추가했다. 종목의 공식 기록은 기존 추정가와 섞지 않는다.
- 이번에는 공식 일별 차트, 전광판의 지수 추가, ETF별 상세 페이지, 한국·미국 20종목 확대, 나스닥·미국 ETF를 구현하지 않았다. ETF는 국내 거래량 순위로 한정한다.

## 데이터 경계와 산식

`/api/market/official-daily?kind=stock&symbol=005930`, `kind=indices`, `kind=etf`가 별도 서버 공급자를 사용한다. 주식 symbol은 기존 국내 카탈로그 allowlist로 한정하며 임의 입력으로 캐시가 무한 증가하지 않는다.

- 주식은 `getStockPriceInfo`의 `likeSrtnCd`로 조회한 뒤 응답 코드가 정확히 같은지 검증한다. 지수는 `getStockMarketIndex`의 `idxNm`을 코스피·코스닥으로 제한한다.
- ETF는 `getETFPriceInfo`의 최근 14일 전체 페이지를 모은 뒤 실제로 확보된 가장 최근 기준일만 선택한다. 거래량 내림차순·동률 종목코드 순으로 10개를 선택한다. 가격·거래대금 순위와는 다르며 레버리지·인버스도 원천 목록에 포함되면 표시한다.
- API `fltRt`는 퍼센트이므로 내부 비율은 `fltRt / 100`이다. 값 `.17`도 0.17%로 처리한다. 종가는 원본 `clpr`, OHLC는 `mkp/hipr/lopr`, 거래량은 `trqu`다.
- 불가능·미래 날짜, 비정상 숫자, 음수 거래량, OHLC 범위 모순, 중복 종목/날짜를 거부한다. 거래 정지 등의 OHLC 0은 미제공으로 표시하고 실제 거래량 0은 유지한다.
- 페이지 크기/번호/totalCount/수집 건수 일치를 확인한다. 페이지 40회·총 20,000건·페이지 body 5MB·조회 30초 상한을 두며 일부 수집 실패를 성공한 순위로 반환하지 않는다. 20,000건 상한을 넘는 경우 조용히 잘라내지 않고 수집 전략 재검토가 필요하다.
- 가장 최근 기록이 14일을 넘긴 종목은 숫자 표시를 중단한다. 주식의 정상적인 90일 과거 이력은 이 제한과 구분한다. 지수별 최신 날짜를 서버와 UI에서 각각 검사한다.

## 인증·캐시·확장성

서버 `.env.local`의 `DATA_GO_KR_SERVICE_KEY`만 사용한다. 저장된 퍼센트 인코딩 키는 한 번 디코딩 후 URLSearchParams로 인코딩해 이중 인코딩 403을 방지한다. 키나 인증 URL, 원본 외부 오류 메시지를 브라우저 응답·로그에 남기지 않는다. 키 미설정은 `NOT_CONFIGURED`, 일반 실패는 `UNAVAILABLE`, 잘못된 요청은 `INVALID_REQUEST`로 반환한다.

기존 createCachedProvider를 사용한다. 프로세스별 1시간 캐시·동시 요청 병합·실패 cooldown 1분과 점진적 증가를 적용한다. 원천 실패 시 허용 기간 내 이전 정상값에는 stale을 붙인다. 브라우저는 mount·보이는 탭 5분 간격·수동 재시도 시 확인하며 종목 변경/unmount 후 오래된 응답을 폐기한다. 정상 응답에는 HTTP 캐시, 실패·stale에는 no-store를 적용한다.

공유 DB나 수집 스케줄러를 추가한 것은 아니다. 다중 서버·1,000명 부하와 공개 Oracle 배포에 대한 성능 보장은 아직 없으며, 서버 재시작 시 캐시는 다시 채워진다. 사용자별 5초 원천 요청은 하지 않는다.

## 참고자료와 이유

2026-09-07 각 공식 페이지에 포함된 Swagger JSON의 host, operation, query parameter, 응답 필드를 직접 확인했다. 외부 블로그의 비공식 endpoint를 복제하지 않았다.

- [금융위원회 주식시세정보](https://www.data.go.kr/data/15094808/openapi.do): 정규시장 일별 OHLC·전일 대비 필드, 다음 영업일 오후 1시 이후 제공 안내.
- [금융위원회 지수시세정보](https://www.data.go.kr/data/15094807/openapi.do): 코스피·코스닥 명칭 검색과 일별 기록.
- [금융위원회 증권상품시세정보](https://www.data.go.kr/data/15094806/openapi.do): ETF 전용 operation, 거래량·일자·페이지 필드. 실제 응답 기준일을 확인하고 실시간 문구로 표시하지 않았다.
- UI/UX skill의 Table Handling 지침을 참고해 좁은 화면에서 보조 열을 줄이고 표 내부 넘침으로 페이지 전체가 깨지지 않게 했다. 기존 색상 token과 PriceChange를 사용했다.

## 검증 이력

- 최종 전체 검증: 78개 테스트 파일, 539개 통과·6개 skip. TypeScript 검사, lint, production build 모두 통과했다. 기존 Vinext route 분류 안내는 남아 있다.
- 수정 후 read-only 재리뷰에서 지수별 날짜 만료 문제 해결을 확인했고 새로운 문제는 발견되지 않았다.
- 인증 검증 후 실제 로컬 read API에서 삼성전자 62개 일별 기록, 코스피·코스닥 2개, ETF 10개를 확인했다. 세 데이터의 확인 당시 기준일은 2026-09-04다. 응답값을 코드에 고정하지 않았다.
- read-only 코드 리뷰에서 두 지수의 날짜가 다를 때 UI가 만료된 이전 지수를 남길 수 있음을 발견했다. 9월 3일/4일 지수를 9월 18일에 재시도하는 실패 테스트로 재현한 뒤 종목별 최신 날짜 검사로 수정했다.
- ETF가 더 이상 준비 화면이 아니므로 기존 미연동 메뉴 테스트는 뉴스만 대상으로 유지하고 실제 ETF 분리·오류/빈 응답 테스트를 추가했다.
- 실제 다크 모드 브라우저에서 ETF 순위와 기준일을 확인했다. 모바일 실기기 및 전체 접근성 인증은 미실시다.
