# 공식 일별 기록 UI와 커뮤니티 작업 순서

> 이 문서는 승인·신청 대기·인증 진단 과정의 이력이다. 이후 실제 주식·지수·ETF 연결 결과는 [공식 일별 데이터 연동](./2026-09-07_공식_일별데이터_연동.md)에 기록한다.

## 후속 확인: 활용신청·인증 검증 완료

2026-09-07 사용자가 3개 활용신청 후 `.env.local`의 서버 전용 `DATA_GO_KR_SERVICE_KEY`를 저장했다. 아래 미신청 기록은 이전 단계의 이력이다.

- 최초 요청은 세 API 모두 HTTP 403, `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`(30)를 반환했다.
- 저장된 값은 퍼센트 인코딩 형태였다. 이를 그대로 URLSearchParams에 넘기면 이중 인코딩된다. 파일을 변경하지 않고 메모리에서 한 번 디코딩한 뒤 요청하자 세 API 모두 HTTP 200 / 결과 코드 `00`을 반환했다. 이 검증에서는 원인이 활용 권한이 아닌 키 인코딩임을 확인했다.
- 공식 페이지 내 Swagger의 host/path를 확인해 `GetStockSecuritiesInfoService/getStockPriceInfo`, `GetMarketIndexInfoService/getStockMarketIndex`, `GetSecuritiesProductInfoService/getETFPriceInfo`에 각각 1건 조회했다. 세 응답의 샘플 기준일은 `20260904`였다. 최신성·전체 이력·ETF 순위 완전성을 검증한 것은 아니다.
- 인증키와 인증 URL은 문서·로그에 남기지 않는다. 이후 서버 연동은 Encoding/Decoding 형식을 안전하게 처리해야 한다. 현재 디코딩은 진단 요청에서만 적용했으며 UI/API 연동 코드를 구현한 상태는 아니다.
- 기존 입력값을 다시 바꿀 필요는 없다. 공공데이터 실제 기록 UI, 캐시·날짜 검증·페이지 수집은 다음 구현 대상이다.

## 승인과 현재 범위

2026-09-07 사용자가 현재 추정가와 공식 일별 기록을 구분하는 UI 구성을 승인했다. 이어서 공공데이터포털 3개 API는 아직 활용신청하지 않았다고 확인했다. 이번에는 인증 없이 가능한 기존 화면 정리만 구현하며 공식 숫자·연동 성공을 가장하지 않는다.

## 승인된 화면 구성

- 종목 상세: 종목명·현재 가격·등락률·가격 성격·공급자 기준 시각 → 기존 차트 → 공식 일별 기록. 차트 OHLC와 비교 기준은 현재 데이터의 의미를 유지한다.
- 공식 기록: 확보된 날짜의 종가·전일 대비·거래량을 먼저 보여주고, 과거 기록을 펼치면 날짜별 OHLC·거래량을 제공한다. 추정가와 다른 시점의 종가를 비교해 오차율이라 부르지 않는다.
- 공식 일별 차트를 추가하는 차수에는 추정 흐름과 별도 탭으로 분리한다. 공식 일별 데이터에 분봉 선택을 노출하거나 서로 다른 원천을 하나의 캔들로 합치지 않는다.
- 시장 지표: 국내 주가지수·일별 → 환율 → 금 연동 PAXG → 시장 심리 순서. 비트코인 심리는 BTC 상세와 시장 지표 양쪽에 유지한다. 한국·미국 미연동 안내는 짧게 표시한다.
- ETF: 국내 ETF 일별 거래량 TOP 10. 같은 기준일의 전체 페이지 수집 완료 후 순위를 계산한다. 미국 ETF·실시간 인기 순위로 오인시키지 않는다. 모바일은 종목·가격·등락률 위주로 표시한다.
- 미연동, 조회 중, 미제공, 실패, 이전 정상 데이터의 갱신 지연을 구분한다. 출처·산식은 팝업으로 모으되 날짜·가격 성격 및 필수 출처 표시를 숨기지 않는다.

## 이번 적용

- 종목 상세에서 긴 데이터 근거 영역을 기존 Dialog UI를 이용한 팝업으로 전환했다. 공급자·기준 시각·계산 입력·주식/FX 주의 문구를 유지한다.
- 가격 요약 바로 아래에 차트를 배치하고 OHLC 요약은 차트 아래로 이동했다. 선택한 봉 단위를 명시했다. 데이터 수집·추정 산식은 변경하지 않았다.
- 시장 지표에서 국내 일별 지수 준비 영역을 맨 위에 두고, 한국·미국 주식 심리의 큰 빈 카드를 한 줄 안내로 축소했다. 실제 지수 값은 연결하지 않았다.

## 아직 미구현 / 필요한 설정

공식 일별 데이터 API, 종목 공식 기록 영역·과거 표·공식 차트, ETF 순위, 전광판의 실제 지수 값은 미구현이다. 인증키가 없는 상태에서 작동하지 않는 원격 연동이나 예시 숫자를 production UI에 추가하지 않는다.

사용자는 아래 세 데이터셋의 활용신청을 진행한다. 키는 채팅·Git에 올리지 않고 서버용 환경변수에만 보관한다. 실제 요청 명세와 응답 기준일을 확인한 뒤 환경변수 이름과 저장 위치를 안내한다.

- [금융위원회 주식시세정보](https://www.data.go.kr/data/15094808/openapi.do)
- [금융위원회 지수시세정보](https://www.data.go.kr/data/15094807/openapi.do)
- [금융위원회 증권상품시세정보](https://www.data.go.kr/data/15094806/openapi.do)

공식 주식·지수 페이지는 기준일 다음 영업일 오후 1시 이후 제공한다고 안내한다. 실제 정규장 가격 불일치를 해소하는 실시간 피드가 아니다. 증권상품의 상세 응답 계약은 아직 검증하지 않았다. 전체 조사 이유와 라이선스 범위는 [공급자 검토](../reference/2026-09-07_공개용_시세_공급자_검토.md)를 참고한다.

## 커뮤니티는 언제 진행하는가

이번 인증 없이 가능한 UI 정리 다음 차수에 진행한다. API 신청 대기가 커뮤니티 착수를 막지 않으며 뉴스·미국 시세·모든 지표의 완성을 기다리지 않는다.

현재 글·댓글·신고·관리자 숨김/복구·제재·운영 로그·보존 정책은 구현되어 있다. 이 worktree는 개인 환경변수를 복사하지 않았고 공개 flag가 기본 false라 메뉴가 숨겨져 있다. 기능이 삭제되거나 아직 처음부터 만들어야 하는 상태가 아니다.

다음 순서:
1. 개발용 커뮤니티 설정과 기존 Supabase 연결 상태를 비밀값 노출 없이 확인한다. 공개 gate를 우회하지 않는다.
2. 이미 게시판형으로 정리된 목록과 글 상세·댓글·작성 흐름을 현재 디자인에 맞춰 확인하고 필요한 UI 보완 범위를 확정한다.
3. 관리자 신고·숨김·삭제 대기·제재·운영 로그 화면의 디자인을 통일한다. 권한과 정책은 UI 개선 때문에 변경하지 않는다.
4. 익명 인증·CAPTCHA·작성·댓글·신고·숨김·복구를 실제 환경에서 재검증한다. 공개 배포는 운영 설정·백업·보존 scheduler·문의/처리 사실 검증을 별도로 통과해야 한다.
