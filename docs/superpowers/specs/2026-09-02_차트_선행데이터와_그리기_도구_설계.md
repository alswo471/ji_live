# 지투라이브 차트 선행 데이터·그리기 도구 설계

> 상태: 기술 검증 후 0.4.0 적용 보류 — 전체 실제 OHLCV 공급자 확보 시 재검토

## 최종 제품 결정 (2026-09-02)

이 문서는 보조지표와 선 그리기의 기술 검토 이력으로 보존한다. 프로토타입으로 warm-up, MA 120·180과 SVG 선 그리기까지 구현했지만 0.4.0 공개판에서는 제거했다. 현재 한국 주식 차트가 KRX 전체 실제 이력이 아니라 공급자 상장 이후의 해외 파생상품·합성환율 기반 추정 데이터이므로, 계산된 이동평균과 추세선이 증권사 수준의 장기 분석 의미를 가진다고 오인될 수 있기 때문이다.

합법적으로 공개 재배포할 수 있는 장기 실제 OHLCV, 수정주가·액면분할 기준과 충분한 이력이 확보되기 전까지 아래 내용은 적용 계획이 아닌 검토안이다.

## 1. 배경

상세 차트에 MA 5·20·60·120과 사용자 지정 이동평균선을 추가했지만, 현재 candle 요청 범위가 화면의 초기 표시 범위와 같다. 이동평균은 선택 기간만큼 앞선 종가가 있어야 첫 값을 계산할 수 있으므로 MA 120은 차트 중간부터 시작하고 MA 180은 점이 없거나 한 점만 생겨 선으로 보이지 않는다.

사용자가 원하는 장기 범위는 2017년부터 현재까지다. 현재 한국 주식 차트 공급자인 Hyperliquid `xyz:SKHX`를 직접 조회한 결과 일봉 최초 시각은 2026-02-19, 월봉 최초 시각은 2026-02-06이었다. 상장 이전 데이터가 공급자에 존재하지 않으므로 2017년부터의 값을 현재 알고리즘으로 생성하지 않는다.

## 2. 목표

- MA 120·180과 2~240 사용자 지정 MA가 계산 가능한 구간에서는 초기 viewport 왼쪽부터 이어지게 한다.
- 이동평균 계산용 선행 candle과 사용자에게 처음 보여주는 viewport를 분리한다.
- 데이터가 부족하면 선을 임의 연장하지 않고 부족한 이유와 보유 candle 수를 안내한다.
- 상세 차트에 추세선·수평선·수직선을 직접 그리는 도구를 제공한다.
- 그린 선은 서버에 전송하지 않고 현재 기기의 해당 브라우저에만 종목·봉 단위별로 보존한다.
- 2017년 장기 이력은 합법적 공개 재배포가 가능한 별도 데이터 공급자 확보 전까지 미제공으로 둔다.

## 3. 제외 범위

- Hyperliquid 상장 이전 가격을 역산·보간·복제하지 않는다.
- 실제 KRX 과거값과 파생 추정값을 하나의 연속 실제 시세처럼 합치지 않는다.
- 이번 작업에서 RSI·MACD용 별도 하단 pane을 추가하지 않는다.
- 서버 계정이나 사용자별 클라우드 저장소를 만들지 않는다.
- TradingView 위젯 또는 라이선스형 Charting Library로 차트 엔진을 교체하지 않는다.

## 4. 확인된 원인과 데이터 한계

### 이동평균선

기간이 `P`인 단순 이동평균의 첫 값에는 `P`개의 종가가 필요하다.

```text
SMA(P, t) = close[t-P+1 ... t]의 합 / P
```

현재 `fetchHyperliquidCandles`는 다음 범위만 요청한다.

```text
startTime = endTime - viewport.visibleSeconds
```

따라서 화면에 120개 candle을 보여주면서 MA 120을 계산하면 첫 119개 candle에는 선이 없다. 해결하려면 화면 범위 앞에 최대 지원 기간만큼의 warm-up candle이 필요하다.

### 장기 이력

2026-09-02 확인 결과:

| 상품 | 주기 | 공급자 최초 candle | 2017년까지 제공 여부 |
| --- | --- | --- | --- |
| `xyz:SKHX` | 일봉 | 2026-02-19 | 불가 |
| `xyz:SKHX` | 월봉 | 2026-02-06 | 불가 |

요청 시작 시각을 2017년으로 보내도 공급자는 실제 상장 이후 candle만 반환했다. 현재 공급자 범위에서는 2017년부터의 장기 실제 차트를 구현할 수 없다.

## 5. 선행 candle 설계

### 공통 정책

- 사용자 지정 MA 최대값과 동일한 `240`개를 warm-up 목표로 사용한다.
- 화면 초기 범위는 기존 `getCandleViewport(interval).visibleSeconds`를 유지한다.
- API는 `화면 범위 + warm-up 240개`를 반환한다.
- 차트는 전체 데이터를 지표 계산에 사용하되 초기 viewport는 기존 화면 범위만 보여준다.
- 공급자에 존재하는 데이터가 목표보다 적으면 받은 데이터만 사용한다.
- 첫 실제 candle 이전 값을 만들지 않는다.

### 주기별 목표 수량

각 주기의 화면 목표 candle 수에 240개를 더하되 공급자의 단일 요청 한도와 실제 보유 기간을 넘지 않는다.

| 주기 | 화면 범위 | warm-up | 처리 방식 |
| --- | --- | ---: | --- |
| 1분 | 최근 2시간 | 240개 | Hyperliquid 범위 확대, Bithumb 분봉 pagination |
| 15분 | 최근 1일 | 240개 | 동일 |
| 1시간 | 최근 5일 | 240개 | 동일 |
| 4시간 | 최근 1개월 | 240개 | 동일 |
| 일봉 | 최근 6개월 | 240개 | 공급자 상장일부터 가능한 만큼 |
| 주봉 | 최근 2년 | 240개 | 공급자 상장일부터 가능한 만큼 |
| 월봉 | 최근 10년 | 240개 | 공급자 상장일부터 가능한 만큼 |

### 환율 candle

한국 주식 원화 candle은 `파생 OHLC × 시점별 KRW-USDT OHLC`이므로 파생 candle만 늘리면 안 된다. Bithumb KRW-USDT도 같은 시간 범위를 조회한다.

- 요청당 허용 count를 넘으면 `to` 시각을 이전 페이지로 이동해 순차 조회한다.
- 시간 중복을 제거하고 오름차순 정렬한다.
- 파생 candle 시각보다 미래인 환율은 기존과 동일하게 사용하지 않는다.
- 환율이 없는 candle은 임의로 채우지 않는다.

## 6. 지표 가용성 UI

- 설정한 기간보다 candle 수가 적으면 해당 지표를 그리지 않는다.
- 설정 패널에 `180선 · 데이터 196개`처럼 확보 수량을 표시할 수 있는 기반을 둔다.
- 계산 가능한 값이 한 점뿐이면 선으로 오인시키지 않고 미표시한다.
- 장기 주기에서 이력이 부족할 경우 `공급자 상장 이후 데이터만 제공됩니다`를 차트 아래에 표시한다.
- 데이터 부족과 사용자가 지표를 끈 상태를 서로 다른 상태로 관리한다.

## 7. 선 그리기 도구 범위

### 1차 도구

- 추세선: 시작점과 끝점의 시간·가격을 연결
- 수평선: 선택 가격을 전체 보이는 시간 범위에 표시
- 수직선: 선택 시각을 전체 가격 영역에 표시
- 선택 도구: 기존 선 선택
- 삭제: 선택한 선 삭제
- 실행 취소: 마지막 추가·수정·삭제 되돌리기
- 전체 지우기: 현재 종목·봉 단위의 선만 제거

### 스타일

- 색상
- 두께: 1·2·3px
- 선 종류: 실선·점선
- 선택된 선은 끝점 handle과 굵은 outline으로 구분
- 색상만으로 종류나 선택 상태를 전달하지 않는다.

### 입력 방식

- PC: 첫 클릭으로 시작점, 두 번째 클릭으로 끝점 확정
- 모바일: 첫 탭으로 시작점, 두 번째 탭으로 끝점 확정
- `Escape`: 작성 취소
- `Delete` 또는 `Backspace`: 선택한 선 삭제
- 그리기 모드에는 버튼의 `aria-pressed`, 상태 안내와 명확한 cursor를 제공한다.
- 차트 이동·확대와 그리기 모드가 충돌하지 않도록 그리기 모드에서만 overlay가 pointer 입력을 가로챈다.

## 8. 그리기 데이터 계약

```ts
type DrawingType = 'trend-line' | 'horizontal-line' | 'vertical-line'

type DrawingPoint = {
  time: number
  price: number
}

type ChartDrawing = {
  id: string
  type: DrawingType
  points: DrawingPoint[]
  style: {
    color: string
    width: 1 | 2 | 3
    lineStyle: 'solid' | 'dashed'
  }
}
```

- 추세선은 2개 point를 사용한다.
- 수평선은 선택 가격을 가진 1개 point를 사용한다.
- 수직선은 선택 시각을 가진 1개 point를 사용한다.
- 저장할 때 유효한 유한 숫자, 지원 type, 허용 style만 보존한다.
- 잘못된 로컬 데이터는 화면 전체를 깨뜨리지 않고 해당 drawing만 무시한다.
- 변조되거나 과도하게 큰 저장값이 렌더링을 막지 않도록 유효한 최신 drawing 최대 200개만 복원한다.

## 9. 렌더링과 좌표 변환

Lightweight Charts의 차트 인스턴스는 그대로 유지한다. 공식 차트·series 좌표 API를 이용해 시간과 가격을 프로젝트 자체 SVG overlay의 화면 좌표로 변환한다. TradingView의 라이선스형 drawing 기능이나 예제 코드를 복제하지 않는다.

- `timeScale().timeToCoordinate(time)`로 X 좌표 계산
- candle series의 `priceToCoordinate(price)`로 Y 좌표 계산
- 확대·축소·이동·resize 후 좌표를 다시 계산
- 화면 밖 point는 데이터에서 삭제하지 않고 보이는 영역만 잘라 렌더링
- 테마 변경은 선 데이터를 재생성하지 않고 배경 대비 스타일만 갱신

그리기 상태와 지표 계산은 `MarketChart` 밖의 순수 reducer·utility로 분리해 테스트한다.

## 10. 브라우저 저장

로그인 없는 공개 서비스이므로 그리기는 서버가 아닌 현재 브라우저에 저장한다.

```text
g2live:chart-drawings:v1:{symbol}:{interval}
```

- 종목과 봉 단위별로 분리한다.
- 서버로 전송하지 않으며 다른 사용자에게 보이지 않는다.
- 같은 사용자의 다른 기기·브라우저·시크릿 모드와도 공유되지 않는다.
- 브라우저 데이터를 삭제하면 그린 선도 삭제된다.
- 저장 실패 시 그리기 기능은 계속 동작하고 `이 브라우저에 저장하지 못했습니다`를 안내한다.

## 11. 컴포넌트 경계

- `lib/market/candle-warmup.ts`: 주기별 warm-up 범위·목표 수량 계산
- `lib/market/chart-drawings.ts`: drawing 검증, reducer, 직렬화
- `components/market/chart-drawing-toolbar.tsx`: 도구·스타일·삭제·undo UI
- `components/market/chart-drawing-layer.tsx`: 포인터 입력과 선 렌더링
- `components/market/market-chart.tsx`: 차트 좌표 API와 drawing layer 연결
- `lib/market/providers/hyperliquid-candles.ts`: warm-up 범위 요청
- `lib/market/providers/bithumb-candles.ts`: KRW-USDT pagination

기존 컴포넌트의 책임을 불필요하게 확장하지 않고, 그리기 상태와 순수 계산을 분리한다.

## 12. 테스트 전략

### 단위 테스트

- 각 interval의 화면 범위에 240개 warm-up을 추가
- MA 180이 선행 데이터 180개 이후부터 계산
- 초기 viewport 왼쪽에 필요한 선행 데이터가 포함됨
- 공급자 실제 이력이 부족하면 받은 최초 candle 이전 값을 만들지 않음
- Bithumb pagination 중복 제거·정렬·종료 조건
- drawing 생성·선택·삭제·undo·전체 지우기 reducer
- 잘못된 localStorage drawing 무시

### 컴포넌트 테스트

- 추세선·수평선·수직선 버튼의 pressed 상태
- Escape 취소와 Delete 삭제
- 사용자 지정 MA 180의 가용·부족 안내
- 종목·interval 변경 시 drawing 저장 key 분리
- 라이트·다크 전환 후 drawing과 지표 유지

### 수동 검증

- SK하이닉스 1분봉 MA 120·180이 초기 viewport 왼쪽부터 연결
- 15분·1시간·4시간의 warm-up과 날짜 경계
- 일봉·주봉·월봉에서 공급자 상장일 이전 미생성
- 375px 모바일 두 번 탭, 1440px 두 번 클릭
- 차트 pan·zoom·resize 후 선 위치 유지

### 전체 검증

```text
pnpm test
pnpm lint
pnpm build
```

## 13. 2017년 장기 데이터 후속 조건

다음 조건을 모두 충족하는 공급자가 확보되면 별도 설계로 진행한다.

- 한국 주식 종목별 2017년 이후 일봉 OHLCV 제공
- 공개 웹사이트 재배포와 광고형 서비스 이용 허용
- KRX·NXT, 수정주가, 액면분할과 종목코드 변경 기준 명시
- 월 10만 원 안팎의 운영 비용 또는 검증 가능한 무료 범위
- API 호출 제한이 서버 cache·영속 저장 구조와 호환

장기 공급자가 추가되면 일·주·월봉은 실제 과거 candle과 현재 파생 추정 candle을 데이터 종류와 경계 시각으로 분리한다. 서로 다른 값을 하나의 실제 시세처럼 연결하지 않는다.

## 14. 성공 기준

- 데이터가 충분한 1분·15분·1시간·4시간봉에서 MA 120·180이 초기 viewport 전체에 표시된다.
- 데이터가 부족한 주기에서는 빈 선이나 조작된 값 대신 이유를 안내한다.
- 추세선·수평선·수직선을 PC와 모바일에서 생성·선택·삭제할 수 있다.
- 그린 선이 종목·interval별로 브라우저에 복원된다.
- 테마 전환과 5초 데이터 갱신으로 drawing, indicator, viewport가 사라지지 않는다.
- 2017년 이전을 포함해 공급자가 반환하지 않은 candle을 생성하지 않는다.

참고 문서는 구현 가능성 확인용 자료다. 라이브러리·위젯·데이터의 저작권과 이용약관은 서로 다르므로 링크를 남겼다는 이유만으로 재배포 권리를 확보한 것으로 간주하지 않는다. 배포·광고 적용 전에 각 공급자의 최신 라이선스, 표시 의무, 데이터 재배포 허용 범위를 다시 검토한다.
