# 대댓글과 원댓글 비공개 처리

사용자는 대댓글 기능을 요청했고, 2026-09-09 원댓글이 삭제·숨김 처리되어도 원문만 가리고 다른 사람이 쓴 답글을 유지하는 정책을 승인했다. 반복 승인 없이 진행하라는 요청에 따라 이 명세를 구현 기준으로 삼는다.

## 범위

- 기존 댓글 아래 한 단계 답글. 답글 자체에 무한 단계 답글은 만들지 않는다.
- 원댓글에 `답글 쓰기`, `답글 N개 보기`를 제공하고 답글은 들여쓰기·날짜·작성자와 함께 표시한다. 일반 댓글과 답글 모두 기존 이모지 입력을 재사용한다.
- 원댓글 목록과 각 답글 목록은 별도로 페이지 처리한다. 기존 최신순·날짜 표기·작성/신고/삭제·1,000자·익명 인증·Turnstile·rate limit을 유지한다.
- 비공개 원댓글에 공개 답글이 있으면 원댓글 자리에는 `삭제·숨김 처리된 댓글입니다.`만 표시한다. 원문·작성자·작성자 UUID·관리 사유는 공개하지 않는다. 비공개 원댓글에는 새 답글을 작성하지 못한다. 이미 있는 공개 답글은 읽기·신고·본인 삭제가 가능하다.
- 비공개 답글 자체는 표시하지 않는다. 게시글 전체가 비공개면 댓글·답글 전체를 공개하지 않는다.
- 기존 1년 보관 및 legal hold 정책을 변경하지 않는다. 보관 기간이 끝나 원댓글이 실제 파기되는 경우에도 타인의 공개 답글을 연쇄 삭제하지 않는다. 원댓글 FK를 SET NULL하여 남은 답글을 일반 댓글로 승격시켜 유지한다.
- 원격 DB 변경·자동 파기 활성화·push·merge는 이번 로컬 구현과 구분한다. 원격 미적용 시 기존 댓글은 읽고 쓸 수 있어야 하고 답글 버튼은 준비되지 않은 기능으로 노출하지 않는다.

## 저장/API

`community_comments.parent_comment_id` nullable UUID FK를 추가한다. 같은 게시글의 공개 원댓글만 대상으로 작성하며, 깊이 1 제한·게시글 공개 여부·작성 제한·멱등 요청을 DB transaction에서도 검증한다. 공개 클라이언트는 답글 연결을 직접 쓰지 못한다. 원댓글 삭제·숨김과 답글 쓰기의 경합 시 검증과 저장이 하나의 잠금 순서 안에서 처리되어야 한다.

댓글 루트 목록은 공개 원댓글 또는 공개 답글이 있는 비공개 원댓글 자리만 조회한다. 답글은 부모 ID별 별도 조회하며 원댓글/답글용 cursor는 용도가 다르면 거부한다. timestamp 원본 마이크로초와 ID를 유지하고 클라이언트에서 전체 데이터를 받아 정렬하지 않는다.

공개 DTO에 `parentCommentId`, `replyCount`, `unavailable`를 추가한다. 비공개 자리 DTO는 본문 고정 안내, 작성자 빈 값, 삭제/답글 쓰기 금지로 제한한다. 서버 전용 읽기 RPC는 비공개 원문을 반환하지 않는다. 기존 관리자 화면은 댓글·답글을 기존 comment 항목으로 관리한다.

원격 DB가 구형이면 정확한 missing RPC/column 오류에만 기존 댓글 경로로 대체한다. 권한·네트워크·기타 오류를 구형 DB로 간주하지 않는다. 댓글 page의 `repliesEnabled`로 UI를 제어한다.

## 검증

TDD로 부모 UUID·다른 게시글·답글에 다시 답글·비공개 부모·중복 요청·다른 payload 재사용을 확인한다. 로컬 SQL transaction 기반 통합 테스트에서 원댓글 비공개 후 원문 비노출/답글 유지, 부모 물리 파기 후 답글 유지, 익명/authenticated 직접 쓰기·RPC 호출 거부를 검증한다. DB reset이나 실제 사용자 데이터 삭제는 금지한다. UI 테스트에서 목록별 더 보기·실패/재시도·중복 클릭·늦은 응답 차단·답글 입력·이모지 재사용을 확인한다.
