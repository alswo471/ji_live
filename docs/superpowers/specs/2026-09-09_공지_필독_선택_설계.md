# 관리자 일반·공지·필독 선택

## 승인 범위

사용자가 승인한 선택지는 `일반 / 공지 / 필독`이다. 별도의 운영자 배지를 대신 넣지 않는다. 이번 단계는 작성 시 종류 선택, 기존 글의 종류 변경/고정 해제, 공지 강조·상단 정렬 및 이미지의 날짜 표기다. 좌측 메뉴·인기글·대댓글·이모지 요청은 다음 단계로 남기며 완료라고 표현하지 않는다. 원격 DB 변경 승인은 아직 받지 않았으므로 local 구현과 검증만 한다.

## 화면 계약

- 관리자 권한이 서버에서 확인된 경우에만 작성 페이지에 `글 종류` 선택을 표시한다. 선택지는 일반(normal), 공지(notice), 필독(required), 기본은 일반이다.
- 일반 사용자는 기존 글쓰기만 사용한다. 운영자는 기존 게시글 상세에서 같은 선택지로 종류를 바꿀 수 있다. 일반으로 변경하면 배지·상단 고정이 해제된다. 이번 단계는 본문 편집기를 새로 만드는 작업이 아니다.
- 필독 → 공지 → 일반 순서, 같은 종류에서는 작성일 내림차순·ID 내림차순이다. 페이지를 넘겨도 누락/중복 없이 이 순서를 유지한다.
- 공지·필독은 이미지처럼 연한 붉은 배경의 텍스트 배지와 강조 제목을 사용한다. 기존 라이트/다크 테마를 유지하고 색상만으로 구분하지 않는다.
- 목록 날짜는 한국 시간 기준 `2026.04.15.` 형식이다. 상세에서도 같은 날짜 형식을 사용하며 기존에 보이던 시각은 보존할 수 있다.
- 저장 실패 시 성공으로 표시하지 않고 입력을 유지한다. 관리자 확인 전·권한 회수·미연결 시 쓰기 권한을 추정하지 않는다.

## 권한·데이터 계약

현재 `requireCommunityAdmin`의 JWT 검증과 `community_admins` 조회를 재사용한다. 브라우저의 이메일·isAdmin·kind 값만 믿지 않는다. 일반 작성 경로로 notice/required를 주입해도 공지가 생성될 수 없어야 한다. 종류 생성·변경은 서버 검증과 DB 제약/RPC 권한 경계에서 보호하며 public/anon/authenticated의 직접 쓰기를 차단한다. 종류 변경 직전 관리자 권한을 다시 확인한다.

신규 글과 선택 종류는 원자적으로 저장한다. 작성 성공 후 별도 요청으로 공지를 지정하는 불완전한 2단계 저장은 금지한다. idempotency key 재요청은 글/변경 이력을 중복 생성하지 않고 다른 작성자의 키를 재사용할 수 없다. 숨김·삭제 글을 종류 변경으로 복구하거나 노출하지 않는다. 기존 신고·관리·1년 보관 정책을 바꾸지 않는다.

변경 감사 정보는 관리자가 누구인지, 대상 글, 이전/새 종류, 시각만 담는다. 새 무기한 개인정보 보관 테이블을 만들지 말고 기존 감사 기록 보존 정책과 연계한다. 관리자 조회/변경 API는 no-store, 실패 시 provider 오류와 키를 노출하지 않는다.

신규 additive migration만 사용하고 기존 migration은 수정하지 않는다. 원격의 이전 schema에서도 일반 글 읽기를 가능한 범위에서 유지하되, 공지 저장을 성공으로 꾸미지 않는다. DB 준비 여부와 권한 여부를 구분해서 안내한다.

## 검증

TDD로 일반 사용자의 위조 요청 거부, 관리자 종류 생성/변경/해제, 유효하지 않은 종류, 숨김/삭제 차단, 재요청 멱등성, 종류별 다중 페이지 순서와 한국 시간 날짜 경계를 검증한다. 실제 로컬 PostgreSQL에서 권한·정렬·원자적 저장·감사 기록을 확인한다. UI는 선택지 노출/비노출, 배지와 날짜, 저장 실패/중복 클릭, 작성 입력 보존을 검증한다. 전체 test·tsc·lint·build와 문서 동기화를 수행한다.
