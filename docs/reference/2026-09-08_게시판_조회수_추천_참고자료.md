# 조회수·추천 참고자료와 선택 이유

2026-09-08 공식 문서를 확인했다. 참고한 배치와 기술 계약을 구분하며, 외부 서비스 UI 자산이나 구현 소스를 복제하지 않는다.

| 자료 | 검토한 내용 | 적용 이유 |
| --- | --- | --- |
| [PostgreSQL Explicit Locking](https://www.postgresql.org/docs/current/explicit-locking.html) | 행 잠금·transaction 수명·deadlock | 같은 글의 집계 요청을 직렬화해 동시에 증가/취소할 때 중복을 막는다. 잠금 순서를 일관되게 유지해야 한다. |
| [PostgreSQL INSERT](https://www.postgresql.org/docs/current/sql-insert.html) | ON CONFLICT | 원하는 추천 상태를 반복 전송해도 관계를 중복 생성하지 않는 경로에 활용한다. toggle 요청의 재시도 문제를 피한다. |
| [PostgreSQL Constraints](https://www.postgresql.org/docs/current/ddl-constraints.html) | unique·foreign key·cascade | 사용자/글 중복 추천을 DB 제약으로 막고 실제 사용자/글 파기 시 종속 관계를 정리한다. |
| [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security) | 노출 schema의 RLS·역할 권한 | browser anon/authenticated 직접 집계 변경을 차단한다. service-role secret은 서버 전용이다. |
| [Supabase Anonymous Sign-Ins](https://supabase.com/docs/guides/auth/auth-anonymous) | 익명 사용자도 authenticated 역할·브라우저 데이터 삭제 시 접근 상실 | 회원가입 화면 없이 중복 방지 식별자를 사용하되, 한 사람이 새 브라우저로 생성한 별도 익명 사용자를 완벽히 판별한다고 주장하지 않는다. |
| [Supabase Cron](https://supabase.com/docs/guides/cron) | PostgreSQL 기반 예약 작업 | 조회 중복 방지 receipt의 수명 관리가 문서 약속에만 머물지 않도록 실제 cleanup 작업을 둔다. |

UI 참고는 사용자가 설명한 네이버 카페의 제목 중심 게시판 관습이다. 특정 카페의 콘텐츠·로고·색상·코드·스크린샷을 수집하거나 복제하지 않았다. 지투라이브의 기존 테마·컴포넌트를 유지한다. 이 기록은 저작권·개인정보 관련 법적 적합성을 보증하는 법률 검토서는 아니다.
