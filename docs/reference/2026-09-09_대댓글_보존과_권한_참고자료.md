# 대댓글 보존·권한 참고 자료

확인일: 2026-09-09. 대상 설계는 [대댓글 설계](../superpowers/specs/2026-09-09_대댓글_설계.md)다. 아래 자료는 기술 설계 근거이며 법률 검토나 타사 코드 사용 허락을 대신하지 않는다. 원문 전문·타사 소스·이미지는 복사하지 않았다.

| 자료 | 확인 내용 | 적용 이유 |
| --- | --- | --- |
| [PostgreSQL Constraints](https://www.postgresql.org/docs/current/ddl-constraints.html) | 외래 키 삭제 동작과 다른 행을 참조하는 CHECK 제약의 한계 | 부모 댓글 파기 시 답글을 연쇄 삭제하지 않는 SET NULL 관계, 같은 게시글·깊이 제한은 단순 CHECK에 맡기지 않음 |
| [PostgreSQL Explicit Locking](https://www.postgresql.org/docs/current/explicit-locking.html) | 행 잠금 충돌과 일관된 잠금 순서 | 원댓글 숨김·삭제와 답글 작성의 동시 요청에서 검증 후 상태가 바뀌는 문제 방지 |
| [Supabase Database Functions](https://supabase.com/docs/guides/database/functions) | security definer/invoker, search_path 및 함수 실행 권한 | 서버 전용 RPC와 고정 search_path, PUBLIC·anon·authenticated의 실행 권한 회수 확인 |
| [Supabase Row Level Security](https://supabase.com/docs/guides/database/postgres/row-level-security) | 테이블 정책·역할별 접근 및 service key의 RLS 우회 | 기존 공개 읽기/서버 쓰기 경계를 유지하고 서버 응답에서 비공개 원문을 제거해야 하는 이유 |

## 프로젝트 코드 확인

- `202609030001_community_schema.sql`: 댓글의 공개 SELECT 열 목록, visible 댓글·visible 게시글에 한정된 RLS.
- `202609040003_community_final_review_fixes.sql`: 작성자 삭제·관리 조치와 1년 파기·legal hold·report/audit 의존성 처리. 이번 기능에서 보관 기간이나 자동 파기 job은 변경하지 않는다.
- `lib/community/write-service.ts`: 서버 인증 뒤 기존 작성 제한·rate limit·멱등 키 경로에 답글을 연결한다.
- `app/community/[id]/page.tsx`: 기존 게시글·댓글 갱신과 Turnstile 검증 경로를 재사용한다.

## 제품 결정의 근거

원댓글 비공개와 다른 사람의 답글 삭제는 별개라는 사용자 승인에 따라 원문을 가리고 답글을 유지한다. 이는 위 기술 문서가 강제하는 정책이 아니라 사용자와 정한 서비스 동작이다. 삭제된 원댓글의 보관 기한을 늘려 연결을 유지하는 대신, 기한 후 실제 파기 시 살아 있는 답글을 일반 댓글로 유지한다.

## 배포 전 확인

- 새 migration은 로컬 테스트와 원격 적용을 별도로 기록한다.
- 원격 적용 전에는 정확한 미지원 오류에만 기존 댓글로 대체하고 새 답글 버튼을 표시하지 않는다.
- 실제 원격 적용 시 기존 행 보존·권한·RPC 노출·자동 파기 job 상태를 확인한다. 대댓글 추가를 자동 파기 활성화 승인으로 취급하지 않는다.
